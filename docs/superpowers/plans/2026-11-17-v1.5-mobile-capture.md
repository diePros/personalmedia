# v1.5 Mobile Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Model policy: **sonnet** implements, **opus** reviews (never fable).

**Goal:** PMS feels like a native scanner app when installed. It has:
- a proper icon everywhere
- an install hint
- an app shell with a bottom tab bar in standalone mode
- a Scan screen that turns one or more camera photos into **one multi-page PDF**
- a one-tap iPhone "Share → PMS" setup using an iCloud-shared Shortcut with an import question

**Owner decisions (2026-11-17):**
- multiple photos become one multi-page PDF
- the owner has an iPhone and will build the Shortcut once from our recipe and share it as an iCloud link
- the installed app opens on Scan
- the browser (non-installed) UI stays as is

**Spec:** §12, §17 of `docs/superpowers/specs/2026-11-16-personal-media-design.md`. The iOS research is in the 2026-11-17 chat:
- Safari has no `share_target`
- Shortcuts install only via iCloud links
- import questions personalise them

## Global Constraints

### Platform and security
- **Strict CSP stays.** No inline JS or CSS, no new external origins, and all JS goes in `static/`. Every new static file is covered by `ASSET_VERSION`, and the service worker precache list is updated. The SW still never caches authenticated responses.
- **No new heavy dependencies.** PDF assembly is a small hand-written PDF writer embedding JPEGs with `DCTDecode` (no `lopdf`, `printpdf` or image crates). Images arriving as PNG are rejected with a clear message, because the client always sends JPEG (see the next point).
- **Client-side image prep** (in `static/scan.js`): each captured photo is drawn to a canvas and downscaled so the longest side is at most **2400 px**, then encoded as **JPEG quality 0.85**. This keeps uploads over Funnel small and fixes EXIF orientation via `createImageBitmap(file, {imageOrientation:'from-image'})`. HEIC from the iOS photo library goes through the same canvas path, since Safari decodes it.
- **Limits:**
  - a scan is at most **50 pages**
  - each page is at most 8 MiB after client prep
  - the whole request is at most `max_upload_bytes`
  - the quota is reserved up front from `Content-Length` (Ruling AC)
- **Plaintext stays in memory.** Page images are held only in memory, in `Zeroizing` buffers where practical, while the PDF is built. They're never written to disk unencrypted. The PDF then goes through `Documents::store_sized`, so the normal encryption, OCR, embedding and switchboard paths apply.

### Look and behaviour
- **Visual language:** reuse the `app.css` CSS variables, in both light and dark themes.
  - Standalone-only styling goes under `@media (display-mode: standalone)`, plus a `standalone` class that `app.js` sets on `<html>` when `navigator.standalone` or that media query matches.
  - Respect `env(safe-area-inset-*)`.
  - Touch targets are at least 44×44 px.
  - Use system fonts; no web fonts.
- **Accessibility:** all controls are labelled, focus is visible, and `prefers-reduced-motion` disables transitions.
- **Manifest `start_url` becomes `/scan`.** `/scan` redirects to `/login` when there's no session, then returns to `/scan`.

### Process
- **Every task ends with:**
  - `cargo fmt --check`
  - `cargo clippy --all-targets -- -D warnings`
  - `cargo test -j 2 --no-fail-fast -- --test-threads=2` with `PM_TEST_MODELS_DIR=$HOME/.cache/pms-test-models`
- **The controller gate before the release also runs `cargo test --release`** (Ruling AI).

## Review Focus
1. A scan of 3 JPEGs produces one valid PDF that `pdfinfo` reports as 3 pages, and `pdftotext`/OCR can read it (`scan_three_pages_builds_valid_pdf`).
2. Bad input never yields a broken document: a PNG, a truncated JPEG, 51 pages, or an oversize page all get a clear 4xx error and no blob (`scan_rejects_bad_input_without_blob`).
3. Quota is reserved up front for scans. Two parallel scans can't exceed it (`scan_respects_quota`).
4. The Shortcut setup token is `read_write`, `metadata_only` and restricted to `inbox`, and creating it requires the password (`ios_setup_token_scope_and_password`).
5. In the browser (not standalone), the existing pages look and behave as before (`non_standalone_layout_unchanged`, a template-level test).

### Task 30: Standalone app shell + Scan screen + multi-page PDF

**Files:**
- `src/pdf.rs` (JPEG → PDF writer)
- `src/web/scan.rs` (GET `/scan`, POST `/api/scan`)
- `templates/scan.html`
- `static/scan.js`
- `static/app.css`
- `templates/base.html` (tab bar shown only in standalone)
- `src/web/pwa.rs` (`start_url`)
- `src/web/mod.rs` (routes)
- Tests: `tests/web_scan.rs`, plus unit tests in `src/pdf.rs`

**PDF writer:** `pub fn jpegs_to_pdf(pages: &[&[u8]]) -> Result<Vec<u8>, PdfError>`.
- Parse each JPEG's SOF0/SOF1/SOF2 marker for width, height and components (1 → DeviceGray, 3 → DeviceRGB; reject CMYK). Reject non-JPEG and truncated input with `PdfError`.
- Page size = image size at 300 dpi → points (`px * 72 / 300`), with the image filling the page.
- Write a correct xref table and trailer.
- Unit tests: valid single and multi page (check with `pdfinfo` when available, otherwise parse the trailer); reject PNG; reject truncated input; grayscale.

**`POST /api/scan`** (session + CSRF header, same auth as `/api/upload`; bearer not needed):
- multipart with `page` fields in order, optional `title`, `tags`, `date`
- reserves quota from `Content-Length`
- collects the pages (limits as in the Global Constraints), builds the PDF and stores it with filename `Scan {YYYY-MM-DD HH-MM}.pdf` (title defaults to that)
- returns `StoreOutcome` JSON
- error JSON uses the same shape as `/api/upload`

**App shell (standalone only):**
- A fixed bottom tab bar: **Documents · Scan · Search · Settings**.
  - Inline SVG icons, the active state highlighted, safe-area padding.
  - The website header is hidden in standalone mode.
  - Search focuses the documents search field.
- No full-page flashes: use htmx `hx-boost` only within the shell links, or keep plain navigation with the SW-cached shell. Pick plain navigation if `hx-boost` conflicts with the CSP or htmx config, and note it.

**Scan screen (`/scan`):**
- **Empty state:** a large circular camera button, centred and at least 96 px. It's an `<input type=file accept="image/*" capture="environment">` behind a styled label. Two secondary buttons below it: **Photo library** (`accept="image/*" multiple`, no capture) and **Files** (`accept="image/*,application/pdf" multiple`; a picked PDF goes to the normal `/api/upload`).
- **After the first photo:** a horizontal thumbnail strip of pages with page numbers, tap to view large, ✕ to delete, drag or arrow buttons to reorder, and a "+" tile to add a page.
  - The primary **Save (N pages)** button is sticky at the bottom above the tab bar.
- **Save sheet:** a bottom sheet with an optional title, quick-tag chips (the user's 8 most recent tags plus `inbox`; tap to toggle), an optional date, and **Upload**.
- **Upload progress:** a progress bar (XHR upload progress) with a cancel button.
- **Success:** a checkmark state, "Saved — text recognition runs in the background", with **Scan another** and **Open document**.
- **Errors:** quota, offline and too large, in plain words, keeping the pages in memory so the user can retry.
- **Offline:** detect `navigator.onLine` and the fetch failure; show a banner and keep the pages.
- The thumbnails use object URLs and are revoked when done. Nothing is persisted in browser storage.

**Tests:**
- `scan_three_pages_builds_valid_pdf`
- `scan_rejects_bad_input_without_blob`
- `scan_respects_quota`
- `scan_page_requires_login_and_returns_to_scan`
- `standalone_shell_markup_present`
- `non_standalone_layout_unchanged`
- the OCR end-to-end on a 2-page scanned PDF built from `tests/fixtures/scan.png` converted to JPEG, model/OCR-gated

**Manual check (controller):** Chrome mobile emulation in standalone display mode. Run through the empty state, add 3 pages, reorder, the save sheet and success, then check `pdfinfo` on the stored doc via the download.

### Task 31: iPhone "Share → PMS" setup

**Files:**
- `src/web/settings.rs`, `templates/settings.html`: a new section "iPhone & iPad sharing"
- `src/config.rs`: `ios_shortcut_url: Option<String>` from `PM_IOS_SHORTCUT_URL`; it must start with `https://www.icloud.com/shortcuts/` or it is ignored with a warning
- `docs/ios-shortcut.md`: rewritten
- `docs/setup.md`
- `docker-compose.yml`: a commented `PM_IOS_SHORTCUT_URL` line

**Settings flow:**
1. A password field and a **Set up iPhone sharing** button create a static token named "iPhone Shortcut", with scope `read_write` + `metadata_only` + tags restricted to `inbox` (created if missing).
2. The result screen shows:
   1. **Get the Shortcut**, which links to `PM_IOS_SHORTCUT_URL`; if that's unset, "Ask the admin for the Shortcut link" plus the docs reference.
   2. Your setup code in a read-only field with a **Copy** button (Clipboard API; the fallback selects the text). The code is `{PM_PUBLIC_URL}|{token}`.
   3. "When the Shortcut asks for the setup code, paste it."
3. The token appears in the normal token list, where it can be revoked.

**`docs/ios-shortcut.md`:** the owner's build recipe, step by step, with the exact action names in the iOS 26 Shortcuts app.
- **Shortcut name:** "PMS". Enable **Show in Share Sheet** with types Images, PDFs and Files.
- **Import question:** on a Text action holding the setup code, with the prompt "Paste your PMS setup code (Settings → iPhone & iPad sharing)".
- **Split** the text by the custom separator `|` into the URL (item 1) and the token (item 2).
- **If** the input contains more than one image, run **Make PDF** from the images so they become one document.
- **Get Contents of URL**: `POST {URL}/api/upload`, header `Authorization: Bearer {token}`, form body with field `file`.
- **Show Notification** "Saved to PMS", or the error message from the response JSON.
- **Share it:** share → **Copy iCloud Link** → set `PM_IOS_SHORTCUT_URL` → restart.
- **Security notes:**
  - The iCloud link contains no token; the import question is answered on each device.
  - Revoke the "iPhone Shortcut" token if the phone is lost.

### Task 32: Handwriting via the user's own AI (MCP page images + transcription) + Notes field

**Owner decision (2026-11-17):** Handwriting is read by the user's own MCP-connected AI (e.g. Claude). PMS can't do it locally yet; see spec §18 for real local HTR later. Page images leave the box **only** for documents whose effective `mcp` level is `full`, and only to `full_text` tokens or apps.

**Files:**
- `src/mcp.rs`: tools `get_page_image`, `set_transcription`, `set_notes`
- `src/user_db/mod.rs`: **index DB migration v3**
- `src/user_db/documents.rs`: notes, text source, FTS
- `src/extract.rs`: page rendering helper reused
- `src/web/docs.rs` and `templates/document.html`: notes field, "Transcribed by AI" badge
- `templates/scan.html` and `static/scan.js`: notes in the save sheet
- Tests: `tests/mcp_handwriting.rs`, `tests/user_db.rs`

**Migration v3 (index DB, Ruling P):**
- `documents.notes TEXT NOT NULL DEFAULT ''`
- `documents.text_source TEXT NOT NULL DEFAULT 'ocr' CHECK (text_source IN ('ocr','transcription','none'))`
- Recreate `documents_fts` with an extra `notes` column (title, filename, tags, notes, content), then reindex every document inside the migration transaction.
- Test: `index_migration_v3_rebuilds_fts_once` (v2 DB with docs → v3, search still works, notes searchable).

**Notes visibility:**
- Notes count as **metadata**: user-typed keywords, searchable at the `metadata` level, like title and tags.
- They can be edited on the document page and in the scan save sheet. Cap 2000 chars.
- MCP `set_notes { id, notes }` needs `read_write`.

**`get_page_image { id, page? (1-based, default 1) }`** returns MCP image content `{type:"image", data:<base64 JPEG>, mimeType:"image/jpeg"}` plus a text item `"page N of M"`.
- **Requires** a `full_text` token or app, effective `mcp` level `Full`, and the tag allow-list. Otherwise it returns "not found" or "token cannot read page images".
- **PDFs:**
  1. Decrypt into the tmpfs job dir.
  2. `pdftoppm -r 150 -f N -l N -jpeg`.
  3. Downscale so the long side is ≤ 1568 px.
  4. Delete the temp dir.
- **Images:** returned as stored (JPEG, PNG or WebP, with the matching `mimeType`) when ≤ 4 MiB; otherwise the error "page too large for preview". PMS has no image crate, and Scan already produces JPEG ≤ 2400 px.
- **Limits:**
  - 20 page images per token per minute (in-memory)
  - page must be ≤ the document's page count
  - response ≤ 5 MiB
- Never cache. Log only the doc id + page.

**`set_transcription { id, text, mode?: "replace"|"append" (default replace) }`:**
- Requires `read_write` + `full_text` + effective `mcp` Full.
- Stores the text into `document_text`, sets `text_source = 'transcription'` and `text_status = done`, reindexes FTS, and drops and re-enqueues vectors (Task 21 path).
- Cap 500 000 chars.

**UI:** the document page shows "Text: recognised by OCR" or "Text: transcribed by an AI assistant" (with the date).

**Docs:** add a setup.md section, "Handwritten notes", with an example prompt for claude.ai: "Find my documents tagged handwritten, read each page with get_page_image, and save a faithful transcription with set_transcription." Include a privacy note: the page images go to the AI provider for the documents you allow.
