# v1.3 Quotas + Web Semantic Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Model policy: **sonnet** implements, **opus** reviews, **fable** only for management or critical reviews.

**Goal:**
1. Storage quotas: an admin-set default (initially 10 GiB) plus a per-user override, enforced on every upload path.
2. A "search by meaning" option in the web UI for the owner's own semantically indexed documents.

**Architecture:**
- **Quotas** live in `system.db` (migration v2). They're admin metadata, like the storage figure the admin page already shows.
- **Enforcement** happens centrally in `Documents::store` through a `Quotas` service with an in-memory usage cache and per-upload reservations. That covers web upload, share-save, MCP `upload_document` and bearer `/api/upload`, because all of them call `store`.
- **Web semantic search** reuses `vectors::search`, generalised from MCP-only to any channel, with the web switchboard filter.

**Spec:** `docs/superpowers/specs/2026-11-16-personal-media-design.md` (§12, §13a, §17a). The owner approved the quota design in chat on 2026-11-17: default 10 GiB, per-user default/custom/unlimited, enforced while streaming, lowering a quota never deletes anything, users see their usage.

## Global Constraints
- **Ruling P:** schema changes only via numbered migrations. `system.db` goes to `user_version` 2; the index DB is unchanged. Write a migration test from a real v1 `system.db`.
- **What counts toward usage:** total bytes of all files under `users/{id}/` (ciphertext blobs + `index.db`), exactly what the admin page shows. In-flight uploads count their reserved bytes. Plaintext bytes streamed ≈ ciphertext size; reserve plaintext bytes + 1 KiB per upload.
- **Default quota:** stored in a new `system_settings(key TEXT PRIMARY KEY, value TEXT)` table, key `default_quota_bytes`. The value is a decimal string, or `unlimited`. The migration seeds `10737418240` (10 GiB).
- **Per-user quota:** `users.quota_mode TEXT NOT NULL DEFAULT 'default' CHECK (quota_mode IN ('default','custom','unlimited'))` and `users.quota_bytes INTEGER NULL` (used only when `custom`).
- **Error text (exact, user-facing):** `Storage quota reached ({used} of {limit} used)`, with sizes formatted by the existing `human_bytes`.
  - Web upload / API: HTTP 413 with JSON `{"status":"quota_exceeded","message":…}`.
  - MCP: tool error with the same message.
  - Share-save page: lists the files that didn't fit.
- **Concurrency:** parallel uploads by the same user must never jointly exceed the quota. Reserve before writing, release on failure or completion, commit the real size on success.
- **Deleting a document** reduces cached usage immediately.
- **Web semantic search:**
  - Only the owner's own documents whose effective `web` level is `full` AND effective `semantic_index` level is `full`.
  - Never available when the model is missing; the UI then explains how to enable it.
  - The query is never logged or put in the browser history: same rules as the live search, `hx-push-url="false"`, pager via htmx.
- Every task ends with `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` run with `PM_TEST_MODELS_DIR=$HOME/.cache/pms-test-models`, with no SKIP.

## Review Focus
1. Two parallel 6 GiB-plaintext uploads under a 10 GiB quota: exactly one succeeds. Use small numbers in tests (`parallel_uploads_cannot_exceed_quota`).
2. Lowering a quota below current usage: nothing is deleted, existing docs stay readable, new uploads get 413 (`lowering_quota_blocks_uploads_only`).
3. Every upload path enforces the quota: web, share-save, MCP `upload_document`, bearer `/api/upload` (`quota_enforced_on_all_upload_paths`).
4. Web meaning-search never shows documents hidden from the web (`web = off`) or not semantically indexed (`web_semantic_search_respects_switchboard`).
5. A v1.2 `system.db` upgrades once and keeps all users and invites (`system_migration_v2_upgrades_once`).

### Task 24: Quotas

**Files:** `src/system_db.rs` (migration v2, settings, quota columns), new `src/quota.rs` (Quotas service), `src/documents.rs` (enforce in `store`), `src/web/{docs,pwa,admin,settings}.rs`, `src/mcp.rs` (map the error), templates `admin.html` / `settings.html` / `share_result.html`. Tests: new `tests/quota.rs`, plus extensions to `tests/web_admin.rs` and `tests/mcp.rs`.

**Interfaces:**
- `SystemDb`:
  - `default_quota() -> Result<Option<u64>>` (None = unlimited) and `set_default_quota(Option<u64>)`
  - `set_user_quota(id, QuotaSetting)` with `pub enum QuotaSetting { Default, Custom(u64), Unlimited }`
  - `UserRow` gains `quota: QuotaSetting`
- `pub struct Quotas` (in AppState and `Documents`):
  - `limit_for(user_id) -> Option<u64>`
  - `usage(user_id) -> u64`: cached; computed by a directory walk on first use, in spawn_blocking
  - `reserve(user_id, bytes) -> Result<Reservation, QuotaError{used, limit}>`, where `Reservation::grow(n)` returns `Err` when it would exceed the limit, and `commit(final_bytes)` / `drop` = release
  - `on_delete(user_id, bytes)`
- `DocError::QuotaExceeded { used: u64, limit: u64 }`.
- **Admin page:**
  - A default-quota form: a number in GiB with one decimal, or a "unlimited" checkbox.
  - A per-user select (default / custom GiB / unlimited).
  - The user list shows `used / limit`.
- **Settings page:** "Storage: {used} of {limit}" (or "{used} (unlimited)").

### Task 25: Web "search by meaning"

**Files:** `src/user_db/vectors.rs` (generalise `search` to take the channel via `ListFilter.access`), `src/web/docs.rs`, `templates/documents.html`, `templates/_results.html`, `static/app.js` (only if needed; prefer plain htmx attributes). Tests: `tests/web_semantic.rs`.

**Behaviour:**
- The documents page search gets a two-option toggle: **Words** (default, the existing FTS search) and **Meaning**. It's a radio group named `mode` with values `words|meaning`, included in the htmx request.
- In Meaning mode the query is embedded (spawn_blocking), and `vectors::search` runs with `access = Some(AccessFilter{Web, Full})` plus the semantic_index Full requirement. Results show the title, date, tags, score as a small "match" badge (0–100 %), and the passage (HTML-escaped, ≤ 300 chars shown).
- Edge cases:
  - Model missing → the results area shows "Search by meaning isn't available yet. Turn on the semantic index in Settings → Access defaults (or per document); the model downloads on first indexing."
  - No indexed documents → "No documents are indexed for meaning search yet."
- The Meaning toggle is hidden from nobody (it's the owner's own data). Rate: one query at a time per session (a simple per-session in-flight flag → 429 if a second one arrives).

**Tests:**

- `web_semantic_query_not_in_access_log`
- `meaning_toggle_rendered`

Commit: `feat(web): search by meaning`.
