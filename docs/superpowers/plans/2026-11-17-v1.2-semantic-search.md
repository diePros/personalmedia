# v1.2 Semantic Search via MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Model policy (owner): **sonnet** implements, **opus** reviews, **fable** only for management or critical reviews.

**Goal:** Users can search their documents by meaning through MCP (`semantic_search`). Embeddings are computed in-process on the ZimaBoard and stored encrypted, and the access switchboard governs them.

**Architecture:** A new `embed` module wraps a small multilingual ONNX model (runtime `ort`). The model is loaded lazily and dropped after 10 minutes idle. The OCR worker pipeline gains an embedding stage: documents whose effective `semantic_index` level is `full` are chunked and embedded, and the vectors are stored in a new `chunk_vectors` table in the user's SQLCipher index (schema migration v2). The `semantic_search` MCP tool does brute-force cosine search over the caller-visible vectors.

**Tech Stack:** Rust (existing crate), `ort` (ONNX Runtime) or `fastembed` (wraps `ort` + `tokenizers`). The choice comes from Task 19. The model file is pinned by SHA-256.

**Spec:** `docs/superpowers/specs/2026-11-16-personal-media-design.md` §17a (plus §13, §13a, §9). The v1 plan's Global Constraints still apply: `docs/superpowers/plans/2026-11-16-personal-media.md`.

## Global Constraints

- **Schema frozen at v1.0.0 (Ruling P).** Every DB change is a numbered `PRAGMA user_version` migration that runs automatically on open. Never edit `SCHEMA_V1`. Migrations must be idempotent and covered by a test that opens a v1-schema DB and upgrades it.
- **No document text, chunk text or vector ever leaves the process or touches disk unencrypted.** Vectors live only in the SQLCipher index DB.
- **Model acquisition (Ruling U):** the model is **not** baked into the image (GHCR's free private storage is 500 MB and the image is already ~320 MB).
  - It's downloaded once from a pinned HTTPS URL, verified against a pinned SHA-256, and stored in `/data/models/<name>/`. Model files are public and contain no user data.
  - The download happens on the first need, or ahead of time via the new CLI `personal-media fetch-model`.
  - A hash mismatch is a hard error. The app never runs an unverified model.
  - Air-gapped alternative: copy the files into `/data/models/<name>/` manually; they're hash-checked on load.
- **Memory:** model load and inference may use a few hundred MB. The model unloads after **10 minutes** idle. Embedding runs in at most **1** concurrent job (it shares the OCR worker pool's spirit and is not parallel). Raise compose `mem_limit` to `1536m`.
- **Chunking:** about **300 model tokens** per chunk with **50 tokens** of overlap. Store each chunk's character offsets into `document_text.content`, so passages are cut from the encrypted text and chunk text isn't stored twice.
- **Privacy rules (spec §17a):**
  - Vectors exist only for documents whose effective `semantic_index` level is `full`.
  - `semantic_search` only considers documents whose effective `mcp` level is `full`, and only for tokens with `content = full_text`.
  - Tag allow-lists apply as in every other MCP tool (Ruling N: no foreign tag names).
  - Dropping a document's `semantic_index` below `full` (override or default) deletes its vectors immediately.
- **Limits:** `semantic_search.limit` ≤ 20 (default 8). `query` ≤ 1000 chars. A passage is at most 1200 chars.
- **Logs:** only document ids, counts, durations and outcomes. Never queries, chunk text or vectors.
- **Every task** ends with `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test`. Tests that need the real model are gated on its presence (print `SKIP`). The Docker build stage downloads the model so those tests run in CI.

## Review Focus

1. A `metadata_only` token, or a document at `mcp = metadata`, must never influence `semantic_search` results, including scores, ordering and counts (Task 22 `semantic_search_ignores_non_full_documents_and_tokens`).
2. A switchboard change below `full` must remove vectors at once, including while an embed job for that document is in flight. The job must not write vectors back afterwards (Task 21 `lowering_semantic_index_mid_job_leaves_no_vectors`).
3. Model download must be hash-verified, and a partial or corrupt download must never be loaded (Task 20 `corrupt_model_file_rejected`).
4. A v1.1 database must upgrade cleanly. Opening it twice must not re-run the migration (Task 21 `migration_v2_upgrades_v1_db_once`).
5. Very long documents (200 pages of OCR text) must embed in bounded memory, using batched inference, and must not block OCR for other users longer than one job (Task 21 `long_document_embeds_in_batches`).

### Task 21: Vector storage, migration v2, indexing pipeline

**Files:**
- Modify: `src/user_db/mod.rs` (migration v2), `src/user_db/` (new `vectors.rs`), `src/extract.rs` (embed stage), `src/user_db/access.rs` (hook for lowering the level), `src/web/docs.rs` and `src/web/settings.rs` (call the deletion hook), `docker-compose.yml` (`mem_limit: 1536m`), `Dockerfile` (fetch the model in the build stage for tests only; the runtime stage stays model-free)
- Test: `tests/vectors.rs`

**Interfaces:**
- Migration v2: `CREATE TABLE chunk_vectors (document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE, chunk_no INTEGER NOT NULL, start INTEGER NOT NULL, end INTEGER NOT NULL, model TEXT NOT NULL, vector BLOB NOT NULL /* f32 little-endian */, PRIMARY KEY(document_id, chunk_no))`, plus `documents.embed_status` (`none|pending|done|failed`, default `none`).
- Functions in `user_db::vectors`:
  - `replace_vectors(conn, doc_id, model, &[(Chunk, Vec<f32>)])`: one transaction
  - `delete_vectors(conn, doc_id)`
  - `docs_needing_embedding(conn, model) -> Vec<String>`: effective `semantic_index` = full, text Done, and no vectors for `model`
  - `set_embed_status`
- Pipeline:
  - After text extraction reaches `Done`, if the effective `semantic_index` is `full`, enqueue an embed job. It uses the same queue and the same `Arc<Unlocked>` rules.
  - `OnUnlock` also enqueues `docs_needing_embedding`.
  - Raising `semantic_index` to `full` (override or default) enqueues. Lowering it calls `delete_vectors` right away, synchronously, in the same request.
  - **Race guard:** the embed job re-checks the effective level inside the write transaction and discards its result if the level is no longer `full`.
  - A model change (the `model` column differs from `MODEL.name`) is covered by `docs_needing_embedding`.

- [ ] **Step 1: Write the failing tests:**
  - `migration_v2_upgrades_v1_db_once`: create a DB with v1.1 code paths (SCHEMA_V1 only), open it with the new code → `user_version` = 2 and the data is intact; reopen → no error
  - `only_full_semantic_index_documents_get_vectors`
  - `lowering_semantic_index_deletes_vectors_immediately`
  - `lowering_semantic_index_mid_job_leaves_no_vectors`: use an injectable pause hook in the job
  - `raising_default_enqueues_existing_documents`
  - `long_document_embeds_in_batches`: about 200 chunks; assert batch count and that peak working set stays bounded (count of vectors held at once ≤ batch size)
  - `vectors_never_plaintext_on_disk`: index DB bytes contain no f32 pattern of a known vector, and no chunk text

- `user_db::vectors::search(conn, query_vec: &[f32], filter: &ListFilter /* access must be Some(Mcp, Full) */, limit: usize) -> Vec<(Document, f32 /*score*/, Chunk)>`
